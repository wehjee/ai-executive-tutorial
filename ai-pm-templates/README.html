AI Product Manager Templates

A set of working templates modeled on how product managers operate at frontier AI labs — Anthropic, OpenAI, and Perplexity. These are not generic PM docs with “AI” bolted on; each one maps to an artifact those teams actually produce.

The templates

# Template What it’s for Modeled on
1 AI PRD Spec a feature whose core behavior is non-deterministic Anthropic (“crisp PRDs that account for non-deterministic behavior”)
2 Model Behavior Spec Define how the AI should behave — objectives, rules, defaults, worked examples OpenAI’s public Model Spec
3 Eval Plan Golden dataset, failure-mode taxonomy, graders, ship thresholds OpenAI (“writing evals is a core PM skill” — Kevin Weil, CPO)
4 Capability Exposure Decision Decide which model capabilities to expose, to whom, and when Anthropic PM charter
5 Launch Readiness Review Go/no-go gate: eval scores, red-team results, rollback plan, iterative-deployment stages Anthropic launch process + OpenAI iterative deployment
6 Safety & Usage Policy Review Usage policies, rate limits, misuse scenarios, mitigations Anthropic (“PMs set usage policies and rate limits”)
7 Quarterly Plan & Weekly Goals Measurable (threshold/boolean) quarterly objectives + “75% weekly goals” Perplexity’s planning system
8 Post-Launch Learning Loop Postmortem + feedback quantification so improvements compound Anthropic post-launch loops + Perplexity postmortems

How to use them

  • Start with #1 (AI PRD) for any new feature; it links out to #2 and #3 rather than duplicating them.
  • #3 (Eval Plan) is the one most PMs skip and frontier labs never do — the quality of your evals caps the quality of your product.
  • #5 (Launch Readiness) is the gate. Nothing ships on vibes; it ships when the numbers in #3 clear the thresholds and #6 is signed off.
  • Documents are meant to replace meetings, not summarize them. Write them so a reader can decide async.
